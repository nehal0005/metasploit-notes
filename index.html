A working dossier on the Metasploit Framework — basics through advanced

Scope, read this first. Metasploit is legitimate, widely taught software. It turns illegal the moment it's pointed at a system you don't own and don't have written permission to test. These notes cover concepts and the standard workflow only — no live exploit code, no steps against a real target. Practise on your own lab VMs, Metasploitable, or authorized platforms like TryHackMe and Hack The Box.

The Idea in one paragraph

Think of a security weakness as an unlocked window. An exploit is the specific move that opens it. A payload is what you do once inside — like switching on a light so you can see the room. Metasploit is an organised toolbox of both, built so testers don't rewrite this from scratch every time.

How an engagement flows

Scope and permissionWritten authorization defining exactly what you may test.
ReconFind live hosts, open ports, running services.
Select moduleMatch a known weakness to an exploit module.
Configure and runSet options, pick a payload, launch.
Post-exploitationConfirm impact, gather evidence, stay inside scope.
Never step 1"Just trying it" on a system without written permission.

Why it matters — Metasploit doesn't decide what's legal. The scope document does.

03

Core commands
search
Find modules — search type:exploit smb
use
Select a module
show options
List settings and what's filled in
set / setg
Fill one setting, or set it for the whole session
info
Full module details and references
check
Test for vulnerability without exploiting
run / exploit
Launch the module
sessions
List and manage active connections

Common options — RHOSTS = target address, RPORT = target port, LHOST/LPORT = your machine, PAYLOAD = which payload to attach.

Always run check before exploit. It's safer and faster for confirming you're on the right track.

Payload types
TypePlain meaning
SinglesSelf-contained, no second download
Stagers / stagesTiny first payload that fetches the full one
Bind shellTarget opens a port, waits for you
Reverse shellTarget connects back out to you

Reverse shells are more common in practice — outbound connections usually pass firewalls more easily than inbound ones.

Meterpreter basics: sysinfo, getuid, ps, background — used within scope, never beyond what's needed.
